# 05 难题通法：把「不会」拆成可验证的小结论

本课面向前端算法面试中的难题：不是靠背答案，而是把复杂题拆成状态、选择、约束与证明，再用小样例逐步验证。

## 学习目标

- 识别难题里的三类信号：规模很大、选择很多、局部最优不可靠。
- 学会把问题改写成「状态 + 转移 + 边界」或「答案空间 + 判定函数」。
- 通过可运行 demo 观察动态规划与二分答案如何降低思考难度。

## 难题四步法

1. **先压缩问题**：只保留输入、输出、约束和一个最小样例。
2. **再找不变量**：问自己「无论怎么操作，什么东西必须保持正确」。
3. **选择范式**：
   - 有重叠子问题：优先尝试动态规划。
   - 要求最小最大值：优先尝试二分答案。
   - 要求所有方案：优先尝试回溯 + 剪枝。
4. **最后证伪**：用反例打掉错误贪心，再保留能解释所有样例的方案。

## 本课练习

Demo 中包含两个典型难题模型：

- `最长递增子序列`：比较动态规划与耐心排序思路。
- `分割数组的最大值最小`：用二分答案把优化题变成判定题。

运行：

```bash
npm run demo -- 05
```

打开终端输出的本地地址，在页面里点击按钮观察每一步推导。

## 面试表达模板

> 我先不急着写最终代码，先确认状态定义和边界。这个题的难点是选择空间很大，所以我会把它转成一个可以逐步验证的子问题；如果过程中发现贪心反例，我会切换到 DP 或二分答案。
